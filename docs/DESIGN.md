# DSH-projects 设计规范

这份文件写给所有改界面的人和 agent。它说明 DSH-projects 为什么长这样、新页面怎么从已有的东西拼出来，以及提交前怎么自查。规则都附上理由：没有理由的规则，第一次不方便时就会被打破。

结构学的是 Raft 开源的设计规范（botiverse/raft-design）：原则 → 变量 → 组件 → 模式 → 决定记录 → 自查清单。内容全部来自产品主人这几天提过的要求，不另外发明。

## 1. 产品是什么，界面为谁服务

DSH-projects 是 DSH 里的一个插件：一个个人助理，加上按项目、任务组织的上下文。主人整天开着它，主要做三件事：看什么等他（待你决定）、看今天发生了什么（时间线）、看所有项目和任务（项目与任务）。

所以界面要做到：

- **安静。** 一天看几个小时也不累，颜色、线和动效都尽量少。
- **一眼知道要干什么。** 先给结论，不先给说明。
- **和 DSH 是一体的。** 我们是宿主里的一块，不另起一套品牌外观。

## 2. 原则

编号固定，其他章节按编号引用。

### P1 白底，不用灰色画布

内容一律放在白底上（暗色模式下是宿主的深色底）。层次靠间距和细线，不靠给画布铺灰。

**为什么。** 试过「灰底加白卡片」，主人的评价是「灰色底就是很丑」。灰色画布让面板看起来像另一个应用，也和 DSH 自己的白色界面接不上。

### P2 只用两种字号，灰字和黑字一样大

标题 16/24 加粗（节标题、对话框标题），其他一律 14/24。同一级的主要文字和次要文字（时间、计数、来源、动词）字号相同，只用颜色区分主次。字重只用来区分角色：正文 400，标签和行标题 500，节标题和分组名 600。

**为什么。** 主人连续三轮指出「字号还是不一样」「层级不对、不舒服」。字号一多，层级就乱：项目名比节标题还大，时间比正文小一号，看起来是三四个层级打架。两种字号加颜色，层级一眼就清楚。

### P3 图标统一 16，文字落在同一条竖线上

行首的图标（项目图标、状态图标、来源头像）一律 16×16，和文字之间留 8。同一块内容里所有文字从同一个左边开始；时间一律右对齐到同一条线。

**为什么。** 「图标前面字号还是不一样」：图标大小不一，文字的起点就跟着乱，看起来不齐。

### P4 线只有 0.5px，一条边界只画一条线

内容内部用细线（hairline），控件和卡片用边线（border），都是 0.5px。两块区域之间只画一条线。卡片左边不画彩色竖线。

**为什么。** 线是用来表达结构的，线多了界面就像一堆格子。

### P5 颜色只有固定含义

所有颜色取 Radix Colors，按色阶约定用：1–2 底色，3–5 组件填充，6–8 边线，9–10 实色，11–12 文字。状态颜色固定：等你黄、进行中蓝、完成绿、出错红，不用橙色。一个颜色说不出它代表什么，就去掉。

**为什么。** 每种颜色只有一个意思，看到颜色就知道发生了什么。黄色只留给「等你」，所以它才醒目。

### P6 不写多余的字

只留标题和关键标签值，用书面语，不口语、不营销。不放说明性文字、副标题、口号、引导段落；不用「·」做分隔符。真需要补充，放进悬停提示。表单标签、读屏名称、不可撤销操作的后果说明必须保留。

**为什么。** 说明文字既弄脏画面，又浪费注意力。好的层级和按钮措辞自己就能说清楚。

### P7 要做的事是一句话，不是按钮

助理的提醒和建议，点一下就把一句完整的请求填进输入框（可改，不会自动发送），由助理去办。「看」（打开任务、打开文件）仍然是直接点开。不做「创建任务」「知道了」「以后不提」这类固定按钮。

**为什么。** 主人希望所有提醒「都是转为 prompt 的输入的感觉」：用一句自己的话交代给助理，比一排按钮更自然。

### P8 助理的形象只是头像

助理的形象是最早那版像素小人，只用作头像：左边栏「个人助理」前面、助理对话的标题旁、它带来的消息前面。不做悬浮球、桌宠，不做别的吉祥物。来自外部应用的消息用该应用真实的标志，不用首字母色块代替。

**为什么。** 主人先后否掉了重画的形象、圆点和悬浮球，最后定为「只作为头像显示」。

### P9 先找现成的参照，不凭空设计

做新界面前先找最接近的成熟产品照着做，优先级：Codex > Claude 桌面端 > Kimi Code > Multica；看板类参照飞书任务面板。量它们真实的数值，不估。

**为什么。** 「不要凭空发明」：成熟产品的形式用户已经学会了，照着做最少出错。

## 3. 变量

所有颜色、字号、圆角、间距只能用变量，不能写死数值。宿主 DSH 提供的变量（`--dsw-alias-*`）优先，我们自己的变量都映射到它们上面，暗色模式跟着宿主一起切换。

| 用途 | 变量 | 值 |
| --- | --- | --- |
| 正文 / 次要文字 | `--mp4-fg` / `--mp4-fg2` | gray-12 / gray-11 |
| 内容底 | `--mp4-bg` | 宿主底色（白） |
| 细线 / 边线 | `--mp4-hair` / `--mp4-hair2` | 宿主边线 l2 / l1，0.5px |
| 悬停 / 按下 | `--mp4-hover` / `--mp4-on` | 宿主交互色 |
| 状态 | `--rx-amber-9` 等 | 见 P5 |
| 字号 | 16 / 14 | 行高都是 24 |
| 圆角 | 12 卡片和对话框，8 行、按钮、输入框、选项格，4 小标记 | 内层 = 外层 − 两者间距 |
| 间距 | 4 8 12 16 20 24 32 | 行最小高 40，左右内边距按层级 4 / 12 / 28 / 36 |
| 选中 | 1.5px #202020 描边 | 色板选中：2px 白 + 1.5px 深色外圈 |
| 按钮 | 主：#202020 底白字；次：透明底灰字 | 内边距 4 / 16，圆角 8 |

## 4. 组件

三个核心标签页（待你决定、时间线、项目与任务）、引导页和设置页都只用下面这些组件拼。需要新组件时先补进这张表，再用。

| 组件 | 长什么样 | 用在哪 |
| --- | --- | --- |
| 节标题 SectionHead | 16 / 600，右侧灰色计数 14，可带一个图标按钮 | 「项目进展」「新消息与建议」「项目」 |
| 分组头 GroupHead | 可选折叠箭头 + 16 项目图标 + 14 / 600 名字 + 右侧灰色时间或「N 件等你」 | 每个项目 |
| 行 Row | 16 状态图标 + 14 文字（灰色动词在前）+ 右侧灰色时间，高 40，悬停浅灰底、圆角 8 | 任务、事件 |
| 消息行 NoteRow | 16 来源头像 + 两行 14（标题 500，正文灰色单行省略）+ 时间，悬停出现关闭 | 新消息与建议 |
| 段落 Story | 14 / 24，缩进对齐分组头文字 | 项目的一段话 |
| 更多 More | 14 灰色「还有 N 件」，点开就地展开 | 折起的行 |
| 状态图标 StatusIcon | 16，Linear 式圆环，颜色见 P5 | 所有状态 |
| 项目图标 ProjectMark | 16 线条图标，颜色由项目决定 | 分组头、侧栏 |
| 头像 Avatar | 16 / 24 像素小人或应用真实标志 | 消息来源、对话标题 |
| 选项格 OptionCard | 带预览的可选格子，圆角 8，选中是 1.5px 深色描边 | 引导页选形象、选模型 |
| 按钮 Button | 主按钮深底白字，次按钮透明底灰字 | 对话框、引导页、空状态 |
| 标签页 Tab | 14，选中浅灰底 | 三个核心标签页 |
| 空状态 Empty | 一句话，必要时加一个主按钮 | 没有内容时 |
| 侧栏切换 SidebarModeSwitch | 16 线性图标（窄栏 18）+ 14 文字，对齐宿主侧栏行与底部入口 | 侧栏底部及「项目」标题旁，在「项目」与宿主「工作区」之间一键切换 |

## 5. 模式

- **细线卡片（11-19 主人选定方向二）。** 三个核心标签页都是白底上的细线卡片：边框 0.5px、14% 灰，圆角 12。一组内容一张卡片（一个项目、一个时段、一组消息）；卡片之间留 12，节与节之间留 24；卡片里的行之间用 8% 的细线隔开，悬停是浅灰底、圆角 8。不用灰色画布，不用阴影。
- **列表。** 分组头 → 行，组与组之间留间距或一条细线；长列表默认显示 3 条，其余折成「还有 N 件」。
- **待你决定。** 只放真正等主人的事：最近在动的项目，每个一段大白话加等他的行；新消息与建议在下面。没动静的项目不上看板。
- **时间线。** 按时段分节（上午、下午、凌晨），每件事一行，时间右对齐，和其他两页用同样的行。
- **项目与任务。** 项目可折叠，任务一行一个，右侧是状态词和时间，回收站放在最后。
- **引导（捏一个你的助理）。** 每一步只问一件事；选项直接画出样子，不让人点了才知道；只有一种选中样式；名字写在形象下面；按钮只有「下一步」和「跳过」。
- **加载、出错、空。** 加载用居中的小转圈加一行灰字；出错说清楚发生了什么、怎么办；空状态一句话。

## 7. 提交前自查

- [ ] 只出现了 16 和 14 两种字号；同一级灰字和黑字一样大。
- [ ] 行首图标都是 16，文字起点在同一条竖线上，时间右对齐。
- [ ] 内容是白底；线都是 0.5px；没有卡片左边的彩色竖线，没有多余阴影。
- [ ] 每个颜色都能说出含义；黄色只表示「等你」。
- [ ] 没有「·」，没有说明文字、副标题、口号。
- [ ] 提醒和建议点了是填进输入框，不是按钮。
- [ ] 只用了第 4 节的组件；新组件已经补进表里。
- [ ] 暗色模式、窄面板都看过一眼。
- [ ] 能找到参照产品的地方照着参照做了，并写明参照了谁。

## 8. 怎么守住

- 代码里的颜色、字号、圆角收进一份变量表，页面只引用变量。
- 测试里加检查：样式表中只许出现第 3 节的字号和圆角，不许出现「·」，不许出现变量表以外的颜色。违反就让测试失败。
- 改规范和改代码放在同一次提交里，并在第 6 节加一条记录。
